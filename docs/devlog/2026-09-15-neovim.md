# 2026-09-15 — Исследование Neovim

> [!info] Мета
> **Дата:** 2026-09-15 · **Тип:** `research` · **Статус:** ✅ решено — **Lazy.nvim**
> **Neovim:** stable 0.12 (2026-02), `vim.pack` experimental

## Цель

Определить границу Nix/Lua и выбрать менеджер плагинов. Учесть принцип: *«Lua существует чтобы конфигурировать Neovim через Lua»*, прозрачность `~/.config/nvim/`, единый Theme.

## Что сделано

- Исследован `vim.pack` (Neovim 0.11 март 2025, 0.12 фев 2026, `vim.pack.add()`, `:packupdate`, `nvim-pack-lock.json`)
- Сравнены 5 вариантов

| Вариант | Воспроизводимость | Удобство | Прозрачность |
|---|---|---|---|
| **A Lazy.nvim** | ★★ (сеть, lockfile) | ★★★★★ | ★★★★ (один файл = один плагин) |
| **B vim.pack** | ★★ (сеть, lockfile) | ★★★ | ★★★ (спека и конфиг разделены) |
| **C Nix/nixvim** | ★★★★★ | ★★ (rebuild ради плагина) | ★★ (Lua в Nix-строках) |
| **D Home Manager** | ★★★★★ | ★★ | ★★ |
| **E Гибрид** | ★★★★ | ★★★★ | ★★★★ |

- Проверено: **LazyVim** — дистрибутив, не нужен; **nixvim** — превращает Lua в Nix, нарушает цель
- Определена граница

| Через Nix | Через Lua |
|---|---|
| `neovim` 0.12 | `keymaps`, `autocmds` |
| LSP/formatters (`pyright`, `stylua`, `nixd`) | `plugin` конфигурация (`setup{}`) |
| `ripgrep`, `fd`, `fzf`, `git` | `options`, `ui` |
| (опционально) pin `vimPlugins.*` | `colorscheme` (из `theme/colors.nix`) |

## Решение (утверждено 2026-09-15)

> [!success] Выбор
> **Вариант A — Гибрид с Lazy.nvim + `lazy-lock.json` в git**

```nix
# home/features/neovim/neovim.nix
programs.neovim.plugins = with pkgs.vimPlugins; [ lazy-nvim ];
xdg.configFile."nvim" = { source = ./nvim; recursive = true; };
# nvim/lazy-lock.json коммитится
```

- Nix даёт `neovim` + `lazy-nvim` + `ripgrep`/`fd`/`git`
- Lua остаётся чистым: `nvim/init.lua` + `lua/core/` + `lua/plugins/` (один файл = один плагин, с `dependencies`, `keys`, `config` вместе)
- `lazy-lock.json` — детерминизм без `/nix/store` на каждый плагин
- `vim.pack` — ветка для эксперимента позже, когда догонит по DSL

## Почему не vim.pack сейчас

- `vim.pack` — будущее Neovim, но в 0.12 ещё **нет** `event/keys/dependencies` DSL → спека и конфиг в разных файлах, теряется discoverability
- Lazy даёт `один файл = один плагин` — идеально для вашего принципа «открыл `plugins/telescope.lua` — понял всё»
- Переход `Lazy → vim.pack` позже — одна правка `init.lua` + `nvim-pack-lock.json`
